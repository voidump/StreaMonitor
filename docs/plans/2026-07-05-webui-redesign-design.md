# StreaMonitor Web UI 改版设计（方案 B：单皮肤重造）

日期：2026-07-05
已确认的决策：方案 B（单皮肤重造）、深色为主、手机/桌面两端并重。

## 目标

- 用一套真正响应式的皮肤取代现有三套皮肤，桌面呈现表格、窄屏呈现卡片，同一套模板。
- 保留 Flask + Jinja2 + HTMX + 无构建步骤的技术底座（适合单用户自托管工具）。
- 删除约 1600 行重复/死代码（kseen715、shaftoverflow）。
- 修复实测发现的体验问题（见下）。

## 非目标

- 不做 SPA / REST API 重写。
- 不改动 Bot、下载器等核心逻辑（另行处理的问题见审计报告）。
- 不新增多用户/权限体系。

## 现状问题（本次实测确认）

1. truck-kun 手机端：表头文字重叠，残留表头区块空占一屏。
2. 录像页桌面端：播放器锁死在约 370px 窄列，右侧 2/3 空白，文件列表挤在夹缝。
3. shaftoverflow 手机端：首屏被添加表单 + 筛选面板占满，标题被磁盘徽章遮挡。
4. 两套可用皮肤 80% 模板重复；kseen715 已损坏（约 570 行死代码）。
5. 已核实：后端 `/video/` 已支持 HTTP Range（send_from_directory 自带，实测 206）。
   拖动问题若存在，在前端播放器或录制中 mp4 的 moov 位置，不需要后端改造。

## 设计

### 皮肤机制收敛

- 只保留一套内置皮肤（目录仍放 `skins/default/`，保留目录结构以防将来需要）。
- `STRMNTR_SKIN` 参数保留但忽略非默认值：启动时打印警告并回退，不让旧配置崩溃。
- 删除 `skins/kseen715/`、`skins/shaftoverflow/` 及对应 static 资产
  （bootstrap、bootstrap-icons、fontawesome 若新皮肤不用则一并删除）。
- 新皮肤依赖：HTMX（已有 vendored 2.0.4）+ 单个自定义 CSS 文件，零自定义 JS 优先
  （沿袭 truck-kun 的做法，确需 JS 的交互控制在一个小文件内）。

### 主页（dashboard）

- 顶栏（sticky）：标题＋磁盘空间胶囊（剩余/总量＋用量条）。手机端不遮挡标题。
- 操作区：
  - 添加主播：桌面为顶栏下方内联表单；手机端折叠为"＋"按钮展开的面板，默认收起。
  - 筛选：折叠面板（沿用现有 cookie 记忆的筛选/排序参数）；手机端默认收起。
  - Start All / Stop All：保留，靠右。
- 列表（一套 DOM，两种形态）：
  - ≥ 900px：信息密集表格（truck-kun 的优点），列＝状态点、站点徽章、国旗/性别、
    用户名（链接到录像页）、运行开关、状态文本、总大小、文件数、操作。
  - < 900px：CSS 切换为卡片流（shaftoverflow 的优点），每卡一行主播，
    首屏直接可见列表，无表头残留。实现用媒体查询＋grid/data-label 技法，不复制模板。
- 录制中的行/卡：红色侧边条＋实时字节数（现有 recording_bytes 已具备）。
- HTMX 局部刷新保持现有频率参数（WEB_LIST_FREQUENCY / WEB_STATUS_FREQUENCY）。

### 录像页

- ≥ 1000px：播放器占主区（max-height 80vh 等比缩放），文件列表为右侧 320px 侧栏。
- < 1000px：播放器全宽，列表在播放器下方。
- 列表项：文件名（时间戳美化显示）、大小、删除按钮（沿用移动端确认删除参数）。
- 排序、当前播放高亮、删除后刷新沿用现有 HTMX 交互。

### 后端配套调整（小）

- 删除死路由：`/dashboard`（引用不存在的静态文件）、`/api/command`、`/clear`。
  `/api/basesettings`、`/api/data` 保留（对外轮询接口，可能有外部用户）。
- 修复 delete_video 竞态：捕获 FileNotFoundError 单独处理为 404 语义。
- Flask 显式指定 static_folder（消除对进程 cwd 的隐性依赖）。
- 上下文构建逻辑保持在 utils/（已相对独立），路由函数只做参数解析和渲染。

### 视觉基调

- 深色为主：近黑背景、深灰卡片/表格底、高对比文字；
  状态色：录制中红、在线绿、离线灰、错误橙、受限黄（沿用现有状态语义）。
- 字体沿用系统栈或现有 Roboto；图标沿用 Feather（已 vendored）。

## 分阶段实施

1. **Phase 1 后端准备**：死路由删除、delete 竞态修复、static_folder 显式化，
   全部带路由级测试（基于已有 create_app() 测试入口）。
2. **Phase 2 新皮肤主页**：模板＋CSS，桌面/手机两形态，preview 实测两种视口。
3. **Phase 3 录像页**：布局重造，播放器自适应验证。
4. **Phase 4 清理**：删除旧皮肤与无用资产、STRMNTR_SKIN 回退逻辑、README 更新。

每阶段结束跑全量 pytest ＋ preview 截图验证（桌面 1280px、手机 375px）。

## 测试策略

- 路由级：test client 断言各页面 200/鉴权 401/删除 404 语义、HTMX 片段可渲染。
- 视觉：dev 启动脚本（假数据、免鉴权）＋ preview 截图人工确认，纳入每阶段验收。
- 回归：现有 10 个测试（鉴权/原子写/超时）保持绿色。

## 风险与缓解

- 有外部脚本依赖 `/api/command` 的可能性低但非零 → 变更记录在 README；
  `/api/data`、`/api/basesettings` 不动。
- 一套模板服务两形态的 CSS 复杂度 → 用容器宽度断点集中在一个 CSS 文件，
  避免模板内分支；preview 双视口验收兜底。
